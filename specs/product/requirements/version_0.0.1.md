# `v0.0.1` MiniMax-H3-V2 API 中转服务需求

## 1. 版本概览

- 版本号：`v0.0.1`
- 项目名称：`minimax-h3-tc`
- 本版本目标：把多个私有 MiniMax-H3 服务包装为可鉴权、可排队、可查询、易于 Docker 部署的对外视频生成 API。
- 问题背景：私有 Gradio 接口使用 32 个位置参数，只返回全局状态和 Gallery，缺少稳定业务任务 ID、用户隔离、单任务取消和标准文件查询流程。
- 解决方案摘要：使用 Go 单进程服务、SQLite 本地数据库、全局 FIFO 和多上游调度器，由中转层生成 `task_id`，按 MiniMax H3 V2 契约返回任务及 `content.url`。

### 1.1 范围内

- Bearer API Key 鉴权及按 Key 的任务、文件隔离。
- 文生视频、单首帧图生视频、首尾帧视频、多模态参考生成。
- 本地任务队列、保护位、多上游实例调度和健康摘除。
- 创建、单任务查询、任务列表和取消/删除。
- SQLite 持久化、幂等提交、重启恢复、7 天逻辑删除。
- Docker、YAML 配置、环境变量覆盖和中文关键链路日志。

### 1.2 范围外

- 页面、管理后台、用户注册、计费、套餐和优先级队列。
- 状态回调；调用方必须主动轮询。
- H3-Context-IR、视频再生成、回调、代理视频流量、对象存储和下载链接签名。
- 删除私有服务上的物理视频文件。
- 暴露 Gradio 快速提示词、UI 配置、模型刷新、打开目录、全局中断或清队列接口。

## 2. 用户与权限

| 角色 | 场景 | 核心诉求 | 权限或限制 |
| --- | --- | --- | --- |
| API 调用方 | 创建并查询视频任务 | 接口稳定、字段兼容、结果可下载 | 只能访问当前 API Key 创建的任务和文件 |
| 部署运维人员 | 配置 Key、上游实例和运行参数 | 单容器、低依赖、可排查 | 通过配置文件和环境变量管理，不提供页面 |

- API Key 在 `config.yaml` 中配置；真实配置不得提交仓库。
- 所有业务接口要求 `Authorization: Bearer <key>`。
- 查询、取消/删除和列表必须同时校验任务 ID 与 API Key 所有权。
- Key 不存在、禁用或不匹配时不得泄露资源是否存在。

## 3. 对外接口范围

| 方法 | 路径 | 类型 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/v2/video_generation` | 官方 V2 | 创建视频生成任务 |
| `GET` | `/v2/query/video_generation/{task_id}` | 官方 V2 | 查询单个任务及成功结果 URL |
| `GET` | `/v2/query/video_generation` | 官方 V2 | 分页查询当前 Key 最近 7 天任务 |
| `DELETE` | `/v2/video_generation/{task_id}` | 官方 V2 + 保护约束 | 取消普通排队任务或删除成功/失败记录 |

标准任务状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`。成功响应在 `task.content.url` 返回视频地址；内部保护位不增加到查询响应。由于防白嫖规则，处于队首保护区的任务虽然对外仍为 `queued`，取消时必须返回不可操作错误，这是本项目对官方“queued 均可取消”语义的明确收紧。

## 4. 视频生成能力

### 4.1 公共规则

- `model` 固定接受官方值 `MiniMax-H3`。
- 请求采用官方 V2 `content` 数组；元素类型为 `text/image_url/video_url/audio_url`，媒体用途由 `role` 表达。
- `resolution` 必填，只接受 `480P`、`768P`、`2K`；`duration` 必填，只接受整数 `4` 至 `15`。
- `ratio` 接受 `adaptive/21:9/16:9/4:3/1:1/3:4/9:16`，并按场景执行官方规则。
- 每次请求必须且只能有一个非空文本项，文本不超过 7000 字符。
- 图片限制：首帧最多 1、尾帧最多 1、参考图最多 9；参考视频和参考音频均最多 3。
- 首尾帧场景与任一 `reference_*` 场景互斥。
- `callback_url` 不在首版范围；请求携带时返回参数不支持错误，不静默忽略。
- 中转层必须完成校验和场景识别，再映射为固定 32 位 Gradio `data` 数组。
- 首版只承诺私有服务可直接访问的 HTTP/HTTPS 媒体 URL；`mm_file://` 和 Data URI 的落地能力在技术方案中列为兼容差异。

### 4.2 支持场景

| 场景 | 输入要求 | 私有模式 |
| --- | --- | --- |
| 文生视频 `t2va` | `content` 仅含文本 | 文生视频 |
| 图生视频 `i2va` | 文本 + `first_frame/last_frame` 图片 | 图生视频 |
| 多模态参考 `r2va` | 文本 + `reference_image/reference_video/reference_audio` | 全能参考视频 |

`/v2/h3_context_ir` 只输出增强提示词，不等同于全能参考视频；私有服务无等价能力，首版不实现。

## 5. 核心业务流程

### 5.1 创建与幂等

1. 校验 API Key、请求结构、模型和媒体约束。
2. 检查每 Key 未结束任务上限 10 和全局上限 100；阈值均可配置。
3. 若提供 `Idempotency-Key`，按 API Key + 幂等键查找 24 小时内记录。
4. 相同请求返回原 `task_id`；请求摘要不同则返回 `409 idempotency_conflict`。
5. 生成不可预测的本地 `task_id`，事务写入 SQLite，状态进入内部可取消排队态。
6. 对外立即返回 `task_id` 和成功 `base_resp`。

### 5.2 调度与结果绑定

1. 调度器维护一个全局 FIFO。
2. 每个健康上游实例最多运行一个任务；不同实例可并行。
3. 调度前保存目标实例的 Gallery 快照，并把实例 ID 与任务绑定到 SQLite。
4. 进入提交阶段前原子锁定任务；此后任务不可取消。
5. 调用 `/submit_minimax_from_slots`，保存 Gradio `event_id` 作为追踪信息。
6. 轮询目标实例的 `/check_and_get_video`，对比执行前后 Gallery。
7. 识别唯一新增视频后保存上游地址，并按对应实例的 `public_base_url` 生成对外结果 URL。
8. 若无法唯一识别结果，任务进入 `failed`，记录脱敏诊断信息，不猜测绑定。

前提：各私有实例必须由本中转服务独占提交；人工或其他程序不得同时向其创建任务。

### 5.3 主动查询与下载

- 调用方轮询 V2 单任务或列表接口；本版本不发送回调。
- `succeeded` 时在 `task.content.url` 返回视频地址，并返回 `resolution/duration/ratio/usage/task_type/modality`。
- 结果 URL 由上游内部视频 URL 替换为对应实例的 `public_base_url` 后得到；只允许替换已校验的协议、主机和端口，路径必须来自上游结果。
- 用户直接访问该地址，中转服务不代理、不缓存视频数据。
- 部署方必须保证调用方可访问每个 `public_base_url`。

## 6. 队列、取消与防滥用

### 6.1 队首保护区

- 默认将全局队列最前方 3 个等待任务置为内部锁定排队态，数量可配置。
- 锁定任务对外仍显示 `queued`，但不可取消。
- 已分配、提交中和 `running` 任务均不可取消。
- 保护位不包含已经运行的任务。
- 队列变化后必须在同一事务或等价原子边界内重算保护位，避免取消与调度并发绕过。

### 6.2 取消接口

- 只有仍在普通可取消排队区的任务可取消。
- 成功取消后任务不再参与调度，并释放未结束任务额度。
- 锁定排队、提交中、生成中或已取消任务返回官方风格参数错误响应。
- `succeeded/failed` 任务执行逻辑删除并返回 `action=deleted,status=deleted`。
- 不调用私有服务的 `/clear_pending_queue` 或 `/interrupt_current_task`。
- 取消接口必须幂等处理已取消任务；具体重复取消响应在接口规格中统一。

## 7. 多上游与故障恢复

- 上游列表支持配置多个 `id`、私有 URL 环境变量名、`public_base_url` 和启用状态。
- 配置中的私有 URL 必须通过环境变量注入，不在 YAML 中写死真实 IP 或凭据。
- 调度器只向健康且空闲的实例分配任务。
- 连续健康检查失败的实例暂停调度；恢复后自动重新加入。
- 明确发生在请求发送前的连接失败可以将任务重新排队并选择其他实例。
- 请求已发送后的超时属于结果未知，不得自动重新提交，避免重复生成。
- 重启后恢复排队任务、实例绑定、Gallery 基线和轮询上下文；若不能唯一恢复运行结果，则标记 `failed`，不得绑定不确定视频。

## 8. 数据与生命周期

### 8.1 核心数据

- API Key 配置标识：不在日志或任务表保存明文 Key。
- 任务：`task_id`、Key 标识、请求摘要、内部/外部状态、上游实例、Gradio event、Gallery 基线、错误、时间戳。
- 结果：直接保存于任务记录，包括上游 URL、公开 URL、宽高、用量和逻辑删除时间，不生成 `file_id`。
- 幂等：Key 标识、幂等键摘要、请求摘要、任务 ID、过期时间。

### 8.2 保留规则

- 任务和结果元数据自创建时间起最多保留 7 天，与官方查询窗口一致。
- 到期后执行逻辑删除；后续查询统一按资源不存在处理。
- 中转服务不删除上游物理文件，也不能撤销调用方已经取得的直接下载链接。
- 清理任务应逻辑删除过期任务并失效幂等和缓存数据，记录清理统计与异常。

## 9. 配置与部署

- 交付 `config.example.yaml`，真实配置由部署方挂载。
- 配置优先级：环境变量 > `config.yaml` > 默认值。
- 配置内容包括 API Key、上游实例、保护位、队列上限、保留时间、幂等窗口、轮询间隔、健康检查、监听地址、SQLite 路径和日志级别。
- 私有地址使用类似 `MINIMAX_UPSTREAM_GPU_1_URL` 的环境变量，并由上游配置引用。
- 关键配置缺失、上游 ID 重复、URL 非法或数据库不可写时拒绝启动。
- 使用 Go 单进程承载 HTTP API、调度 Worker、轮询器和清理器；SQLite 文件挂载 Docker Volume。
- 不依赖 Redis、PostgreSQL、消息队列或 Python 运行时。

## 10. 非功能要求

### 10.1 安全

- Bearer Key 使用恒定时间比较或安全摘要比对；日志禁止输出 Key 和完整敏感媒体 URL。
- 所有任务操作强制进行 Key 所有权过滤。
- 仅允许 HTTP/HTTPS 上游和媒体 URL；SSRF、DNS 重绑定及重定向策略在技术方案中明确。
- 外部错误不返回上游内网地址、调用栈、本地路径或实时日志。

### 10.2 一致性与可用性

- SQLite 状态变更、保护位更新、取消和任务领取必须具备原子性。
- 重启不得丢失已入库任务。
- 单个上游故障不得阻塞其他健康上游继续执行。
- 不设首版吞吐量或延迟 SLA；真实生成性能需人工压测后确定。

### 10.3 可观测性

- 结构化日志至少包含请求 ID、任务 ID、API Key 标识、上游 ID、阶段、耗时、结果和脱敏错误码。
- 关键日志覆盖鉴权失败、入队、保护位变化、领取、提交、轮询、结果绑定、取消拒绝、上游摘除/恢复、重启恢复和逻辑清理。
- 提供服务健康和各上游实例健康状态；不得暴露私有实时日志或系统资源详情给普通调用方。

## 11. 验收标准

| 场景 | Given | When | Then | 人工确认项 |
| --- | --- | --- | --- | --- |
| Docker 启动 | 有有效配置和可写 Volume | 启动容器 | 服务和 SQLite 正常，容器 TCP 健康检查通过 | 目标环境启动确认 |
| Key 隔离 | 两个不同 API Key | 交叉查询任务或文件 | 不返回他方数据 | 安全复核 |
| 三类生成 | 对应合法 V2 content | 创建并轮询 | 参数正确映射，成功返回 `task.content.url` | 真实私有服务联调 |
| 多实例并行 | 至少两个健康独占实例 | 连续提交任务 | 各实例最多一个运行任务且可并行 | 多实例环境确认 |
| 取消成功 | 任务仍在普通排队区 | 发起取消 | 原子取消且永不提交上游 | 并发测试复核 |
| 取消拒绝 | 任务在保护位或已提交 | 发起取消 | 返回 `409 task_not_cancelable` | 防滥用业务验收 |
| 结果绑定 | 上游完成并新增视频 | 轮询 Gallery | 唯一视频 URL 绑定到正确 `task_id` | Gallery 真实格式确认 |
| 直接下载 | 成功任务未逻辑删除 | 查询 task_id | `content.url` 可由调用方直接访问 | 网络与域名确认 |
| 幂等提交 | 同 Key、同幂等键 | 重复同请求/不同请求 | 返回原任务/返回 409 冲突 | 客户端重试验证 |
| 重启恢复 | 存在排队或运行上下文 | 重启容器 | 排队恢复；运行结果可唯一识别或明确失败 | 故障演练 |
| 逻辑清理 | 元数据超过 7 天 | 清理周期运行 | 查询不可见且不删除上游文件 | 时间加速测试 |

自动化可完成单元测试、接口测试、并发状态测试和 Docker 启动测试。真实私有服务联调、多实例并行、生产性能、网络可达性和最终业务验收必须人工确认，本文不声明其已完成。

## 12. 依赖、风险与待确认

| 类型 | 内容 | 影响 | 处理方式 |
| --- | --- | --- | --- |
| 依赖 | 私有实例独占 | 非独占会导致 Gallery 结果错配 | 部署约束 + 启动/运维检查 |
| 依赖 | `public_base_url` 对调用方可达 | 不可达则无法下载 | 上线前人工验证 |
| 风险 | 上游无业务任务 ID | 超时与重启时可能无法唯一恢复 | 单实例单任务、持久化快照、不确定即失败 |
| 风险 | 逻辑删除不释放上游磁盘 | 长期运行会占满磁盘 | 后续增加上游清理机制或删除接口 |
| 风险 | 直接链接无法撤销 | 链接泄露后中转层无法阻断 | 明示边界；后续采用签名 URL/对象存储 |
| 待确认 | Gallery 返回结构、完成判定及 URL 规则 | 影响结果绑定 | 使用真实实例联调确认 |
| 待确认 | V2 分辨率/比例到私有宽高、模型模式和采样步数的映射 | 影响生成结果 | 建立可配置映射并人工验证 |
| 兼容差异 | `mm_file://`、Data URI、callback 和水印能力 | 部分官方输入无法落地 | 技术方案明确拒绝规则与后续扩展点 |
