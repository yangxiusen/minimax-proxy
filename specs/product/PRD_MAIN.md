# MiniMax-H3-V2 中转服务主 PRD

## 1. 产品定位

本项目将多个私有部署的 MiniMax-H3 Gradio API 包装为面向外部调用方的 MiniMax H3 V2 异步视频生成 API。系统负责鉴权、参数适配、本地任务 ID、统一排队、多实例调度、任务状态、结果 URL 映射和防滥用控制，不运行模型，也不提供页面。

## 2. 产品能力地图

| 能力 | 说明 | 首版状态 |
| --- | --- | --- |
| API 鉴权与隔离 | 配置多个 Bearer API Key，任务和文件按 Key 隔离 | `v0.0.1` |
| 视频生成适配 | 文生、单首帧、首尾帧、多模态参考 | `v0.0.1` |
| 本地队列 | FIFO、队首保护位、Key/全局限额 | `v0.0.1` |
| 多上游调度 | 多个私有实例并行，每实例单任务 | `v0.0.1` |
| 主动查询 | `task_id -> task.content.url` | `v0.0.1` |
| 结果生命周期 | 任务与结果元数据保留 7 天后逻辑删除 | `v0.0.1` |
| Docker 部署 | Go 单服务、SQLite、YAML 与环境变量配置 | `v0.0.1` |
| 回调与管理页面 | 不在首版范围 | 不计划于 `v0.0.1` |

## 4. 长期约束

- 运行时代码不得直接依赖 `docs/`；资料只用于需求与接口分析。
- 所有文本使用 UTF-8，代码注释使用中文，关键代理边界记录脱敏结构化日志。
- 私有服务必须由中转服务独占提交，否则无法可靠关联全局 Gallery 中的结果。
- 上游没有稳定业务任务 ID；每个上游实例任何时刻最多运行一个任务。
- 对外严格采用 MiniMax H3 V2 路径和字段，模型值为 `MiniMax-H3`。
- `/v2/h3_context_ir` 只生成增强提示词，私有服务无等价能力，首版不实现。
