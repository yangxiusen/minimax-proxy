# 节点 Key ID 数据库兼容增量

## 1. 变更概览

| 项目 | 内容 |
| --- | --- |
| 影响对象 | `model_service_nodes.api_key_id` |
| 变更类型 | 业务语义调整，不改表结构 |
| 风险等级 | Medium |

## 2. 变更内容

- 变更前：H3 节点将 `api_key_id` 作为有效凭据标识读写，并与加密 Key 一起参与业务比较。
- 变更后：该列仅为 v7 数据库约束兼容占位。H3 创建和更新写入空字符串，查询扫描到局部忽略变量，不进入领域模型、Manager DTO 或相等性判断。
- Legacy 行仍按既有约束保留 `NULL`，避免破坏 v7 CHECK 规则。
- 原因：移除 Key ID 业务概念，同时避免为删除旧列引入 SQLite 表重建和额外迁移风险。

## 3. 执行脚本

本变更不执行 DDL 或数据修复脚本，不新增迁移版本。历史非空值原样保留并在应用层忽略。

## 4. 数据兼容与回滚

- 历史数据受影响：不修改历史值，只改变应用读取语义。
- 数据迁移：不需要。
- 回滚：旧版本仍可读取历史非空值；新版本写入的空字符串满足 H3 行非空约束，但旧业务若强制要求非空内容则需与 Node/Proxy 代码一起整体回滚。
- 外部客户 API Key 表、任务归属字段和回调数据不受影响。

## 5. 验证项

- [ ] v7 历史数据库可直接打开。
- [ ] 历史非空 `api_key_id` 不出现在领域对象和接口响应。
- [ ] 新建和更新 H3 节点写入空字符串占位。
- [ ] Legacy 行约束和行为不受影响。
- [ ] 未产生新的迁移文件或迁移版本。
