# 管理后台与模型节点配置需求增量

## 1. 页面定位变化

现有“MiniMax H3 运行监控”升级为“MiniMax H3 管理后台”，主路径从 `/monitor` 迁移到 `/manager`。任务列表、任务中止/删除/播放和私有服务监控能力全部保留。

页面顶栏右侧在管理员信息前增加“配置”按钮。点击后打开模型服务节点配置弹窗，不离开当前任务和监控页面。

## 2. 节点管理能力

管理员可以：

- 查看全部未删除节点及启停状态。
- 新增节点并填写节点 ID、Gradio 地址、Jobs 地址、公开视频地址、健康路径、提交接口名、查询接口名、轮询间隔和请求超时。
- 在保存前测试草稿配置的 Gradio 与 Jobs 服务连通性。
- 编辑已有节点；节点 ID 创建后不可修改。
- 启用或停用节点。停用节点不再领取新任务，但已有任务继续运行、恢复或中止收口。
- 删除已停用且没有活动任务的节点；删除前必须二次确认。

## 3. 状态与反馈

- 保存成功只表示配置已持久化；节点必须启用且健康检查通过后才显示为可调度。
- 配置应用期间显示“应用中”，健康检查尚未完成时显示“状态未知”，不得提前显示健康。
- 表单必须显示字段级校验错误；网络或服务错误保留用户已输入内容。
- 版本冲突时提示“配置已被更新，请刷新后重试”，并重新加载最新配置。
- 节点存在活动任务时，仅允许从启用改为停用；其他连接修改和删除给出明确冲突提示。
- 节点列表为空时展示新增入口，不把空状态显示成页面故障。

## 4. 配置来源迁移

- 旧版 YAML `upstreams` 仅在升级后的首次启动作为导入来源。
- 导入必须全量成功或全量失败；失败时服务不启动，修正原配置后可再次启动重试。
- 导入完成标记和节点记录在同一数据库事务提交，防止重启重复导入。
- 导入完成后，修改或删除 YAML `upstreams` 不改变运行节点，也不阻止服务启动。
- 若首次启动时 YAML 没有节点，记录导入已完成并以零节点启动，后续通过管理后台添加。

## 5. 兼容性要求

- `GET /monitor`、`GET /monitor/` 和 `GET /monitor/login` 兼容跳转到 `/manager` 对应页面。
- 新管理会话 Cookie 的 Path 为 `/manager`；旧 `/monitor` 会话不迁移，升级后需要重新登录。
- 公共 `/v2` 接口路径、鉴权、任务状态机和输入输出契约不变。
- 已存在任务中的 `upstream_id` 保持原值；节点软删除后历史任务仍能显示节点 ID。

## 6. 权限与安全

- 所有节点读取和写入接口均要求现有管理员账号登录。
- URL 只接受完整 HTTP/HTTPS 地址，不得包含用户凭据、查询参数或片段。
- 节点 ID 仅允许字母、数字、点、下划线和连字符，长度 1 至 64，创建后永久保留且不可复用。
- 管理接口不得返回数据库内部主键、软删除记录或原始上游错误。
- 日志只记录节点 ID、动作、阶段和稳定错误码，不记录节点 URL 或请求体。
