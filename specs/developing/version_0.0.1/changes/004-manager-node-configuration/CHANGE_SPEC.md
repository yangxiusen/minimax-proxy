# 管理后台与模型节点配置变更说明

| 项目 | 内容 |
| --- | --- |

| 变更类型 | 管理能力迭代/配置来源迁移 |
| 优先级 | High |
| 提出日期 | 2026-08-11 |
| 负责人 | 待人工填写 |

## 2. 背景与目标

现有 `/monitor` 是带登录态的任务与私有节点监控页，但模型服务节点只能通过 `config.yaml` 的 `upstreams` 配置，并在进程启动时一次性构建。新增、停用或修改节点都必须编辑文件并重启服务，无法在运行中管理。

本变更将监控页扩展为 `/manager` 管理后台，在页面右上角提供“配置”入口，通过弹窗完成模型服务节点的新增、编辑、启停、连接测试和删除。节点配置持久化到 SQLite，运行时依据数据库期望状态动态装载，不再把 YAML 作为日常节点配置源。

## 3. 已确认决策

- 升级后首次启动时，如果节点表为空，则将旧 YAML `upstreams` 一次性、全量、原子导入 SQLite。
- 首次导入流程完成后写入持久化标记；后续启动忽略 YAML 节点内容，SQLite 是唯一真相源。
- 管理员账号、API Key、队列、任务和生成规格继续由 YAML 管理，不纳入本次配置弹窗。
- `/monitor` 页面入口迁移到 `/manager`；旧页面地址保留兼容跳转，管理 API 和会话统一使用 `/manager`。
- 节点有活动任务时禁止修改连接参数或删除；允许单独停用，停用后不领取新任务，但已归属任务继续收口。

## 4. 验收标准

- 首次升级能把现有合法 YAML 节点完整导入数据库，且不会重复导入或因后续 YAML 修改覆盖数据库。
- 没有 YAML 节点的新安装也能启动并访问 `/manager`，此时公共创建接口按无可用节点返回服务不可用。
- 管理员可在配置弹窗新增、编辑、启停、测试和删除模型节点，刷新页面或重启服务后配置不丢失。
- 启用且健康状态新鲜的节点可动态参与调度，无需重启前置服务；停用节点不领取新任务。
- 节点存在活动任务时，危险修改和删除返回 409；停用操作不打断已归属任务。
- `/monitor` 和 `/monitor/login` 跳转到对应 `/manager` 页面；旧会话不跨路径复用，管理员需重新登录。
- 管理响应和日志不包含 API Key、prompt、媒体 URL、私有响应体或 URL 凭据。

## 5. 不在范围

- 在管理后台编辑管理员账号、API Key、队列、任务保留期或生成规格。
- 多管理员、角色权限、操作审计查询页面。
- 跨进程配置通知；当前部署仍是单前置服务进程和单 SQLite 数据库。
- 修改私有模型服务代码或自动安装其 Jobs API。
- 自动发现局域网模型节点。
