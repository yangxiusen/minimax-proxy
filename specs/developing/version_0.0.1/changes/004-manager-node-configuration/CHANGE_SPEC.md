# 管理后台与模型节点配置变更说明

> 凭据规则已被 `006-node-single-key-conf` 取代：现行 Node 契约只使用一个 32 位字母数字 API Key，不再使用模型节点 Key ID、scope 或 `key_id.secret`。本文相关旧内容仅保留为历史设计记录。

## 2. 背景与目标

现有 `/monitor` 是带登录态的任务与私有节点监控页，但模型服务节点只能通过 `config.yaml` 的 `upstreams` 配置，并在进程启动时一次性构建。新增、停用或修改节点都必须编辑文件并重启服务，无法在运行中管理。

本变更将监控页扩展为 `/manager` 管理后台，在页面右上角提供“配置”入口，通过弹窗完成模型服务节点的新增、编辑、启停、连接测试和删除。节点配置持久化到 SQLite，运行时依据数据库期望状态动态装载，不再把 YAML 作为日常节点配置源。

## 3. 已确认决策

- 升级后首次启动时，如果节点表为空，则将旧 YAML `upstreams` 一次性、全量、原子导入 SQLite。
- 首次导入流程完成后写入持久化标记；后续启动忽略 YAML 节点内容，SQLite 是唯一真相源。
- 管理员账号、API Key、队列、任务和生成规格继续由 YAML 管理，不纳入本次配置弹窗。
- `/monitor` 页面入口迁移到 `/manager`；旧页面地址保留兼容跳转，管理 API 和会话统一使用 `/manager`。
- 节点有活动任务时禁止修改连接参数或删除；允许单独停用，停用后不领取新任务，但已归属任务继续收口。

## 4. 验收标准

- 首次升级能把现有合法 YAML 节点完整导入数据库，且不会重复导入或因后续 YAML 修改覆盖数据库。
- 没有 YAML 节点的新安装也能启动并访问 `/manager`，此时公共创建接口按无可用节点返回服务不可用。
- 管理员可在配置弹窗新增、编辑、启停、测试和删除模型节点，刷新页面或重启服务后配置不丢失。
- 启用且健康状态新鲜的节点可动态参与调度，无需重启前置服务；停用节点不领取新任务。
- 节点存在活动任务时，危险修改和删除返回 409；停用操作不打断已归属任务。
- `/monitor` 和 `/monitor/login` 跳转到对应 `/manager` 页面；旧会话不跨路径复用，管理员需重新登录。
- 管理响应和日志不包含 API Key、prompt、媒体 URL、私有响应体或 URL 凭据。

## 5. 不在范围

- 在管理后台编辑管理员账号、API Key、队列、任务保留期或生成规格。
- 多管理员、角色权限、操作审计查询页面。
- 跨进程配置通知；当前部署仍是单前置服务进程和单 SQLite 数据库。
- 除统一请求校验错误包、授权 scope 回显和契约快照外，不修改私有模型工作流、ComfyUI 适配或自动安装组件。
- 自动发现局域网模型节点。

## 6. 2026-08-13 H3 Node API 契约修订

### 6.1 问题与根因

当前数据库中由旧 YAML 导入的节点使用 `legacy-gradio-v1`，没有 Node API 凭据。管理页面编辑该节点时只提供 `h3-node-v1` 选项，并允许空密钥沿用，导致后端把节点协议切换为 H3、同时继续写入空密钥字段，最终触发 `007_single_endpoint_nodes.sql` 的跨字段 `CHECK` 约束并返回无提示价值的 500。

跨项目审计同时确认，Proxy 虽然分别保存 `api_key_id` 和加密后的 Secret，但 Node 客户端只发送 Secret；MiniMax-H3 实际要求 `Authorization: Bearer <key_id>.<secret>`。现有 Proxy 测试使用预拼接的 `proxy.secret`，因此没有发现生产调用会收到 401。

### 6.2 修订目标

- 旧节点保持可识别、可停用和可删除；转换为 `h3-node-v1` 必须经过明确的“升级协议”动作，并同时提供合法 Key ID 与新 Secret。
- 所有管理写入在访问 SQLite 前完成协议、Key ID、Secret 与“是否可复用已保存密钥”的交叉校验，确定性输入错误返回稳定 400，不再依赖数据库约束兜底。
- Node 客户端以结构化凭据接收 Key ID 和 Secret，并只在请求边界组装 Bearer Token。
- 补齐 H3 执行取消、提交结果未知和轮询短暂故障的恢复语义，避免取消后继续成功或重复生成。
- 用可执行契约检查覆盖路由、鉴权、错误包和 Proxy 实际消费面；接口结论见 `NODE_API_CONTRACT_AUDIT.md`。

### 6.3 修订后的范围

本修订允许对相邻 `Minimax-H3` 项目的内部 Node API 做必要兼容修复，包括统一参数校验错误包和在能力响应中返回当前凭据的授权范围。它不改变公共 `/v2` API，也不把 Node 的维护清理接口接入 Proxy；Proxy 继续使用自己的清理任务和 Node 制品删除接口。

## 7. 2026-08-13 任务 FIFO、视频播放与结果绝对 URL 修订

### 7.1 缺陷证据

- 任务 `815624111920755101` 于 18:41:56 创建，生成阶段于 18:43:22 完成，但其高清修复阶段直到 18:44:43 才开始。
- 任务 `272076440301631191` 于 18:43:09 创建，其生成阶段在两者之间被领取，并于 18:44:39 整体成功。
- 根因是 `ClaimStage` 使用 `ORDER BY stage_order,created_at,id`：后创建任务的生成阶段 `10` 会排在先创建任务的修复阶段 `20` 前面。
- H3 Node API 成功任务只保存 `result_artifact_id`；Manager 列表仍主要读取历史 `result_public_url`，导致已有“播放”前端逻辑拿不到视频地址。
- 公共查询使用 Proxy 签发的 `/v2/files/{artifact_id}/content` 相对路径。该路由属于 Proxy，不属于 `http://127.0.0.1:7860` Node，拼到 Node 地址会访问错误服务。

### 7.2 修订目标

- 每个节点领取当前可执行阶段时，先按父任务 `queue_seq` 选择最早任务，再按该任务的 `stage_order` 执行，避免后任务插入先任务的阶段链。
- 保留多节点并行、节点亲和、延迟重试和恢复能力；不承诺不同节点上的任务按创建顺序完成。
- Manager 已完成任务稳定返回签名 `video_url`，任务列表显示“播放”按钮并在站内弹窗播放。
- 公共单任务和任务列表中的 `content.url` 返回可直接访问的绝对 URL。
- 绝对 URL 基于 Proxy 新增配置 `server.public_base_url`，例如 `http://127.0.0.1:18081`，不得使用 Node 的 `service_url`，也不得信任请求 `Host/X-Forwarded-*` 动态拼接。

### 7.3 范围边界

- 不新增或修改 SQLite 表结构，不回填历史 URL。
- 不暴露 Node API Key、Node 内部 artifact ID 或 Node `service_url`。
- 不改变 `/v2/files/{artifact_id}/content` 的签名、所有权、Range、过期和文件流代理规则。
- 不实现任务优先级、暂停、手工换序或跨节点全局完成顺序保证。
