## 2. 背景与目标

当前 Worker 会轮询私有服务的 Gallery，但私有服务不可访问或恢复后报告空闲且没有新增视频时，任务仍可能无限保持“运行中”。监控台也会因本地存在当前任务而覆盖私有服务的空闲观察，形成假运行并长期占用实例。

本变更建立可恢复、可终止、可审计的任务闭环：

- 使用私有服务已有的 `/api/jobs`、`/api/jobs/{job_id}`、取消和历史能力关联具体模型任务。
- 私有服务崩溃后进入恢复对账；任务丢失时最多自动重试一次。
- 单次执行 10 分钟作为卡死和长期离线的最终保护，不作为正常崩溃恢复的首选触发器。
- 监控任务列表支持二次确认中止、终态删除和成功视频播放。
- 所有终态路径释放实例并清除监控快照，不再无限假运行。

## 4. 验收标准

- 私有服务短暂不可用时任务进入恢复状态；恢复后可按模型任务 ID继续、完成、失败或重试。
- 私有服务重启导致原模型任务丢失时，先检查现有结果，再自动重试一次；再次丢失则失败。
- 私有服务持续离线或指定模型任务持续运行超过 10 分钟时，任务最终失败，不以超时触发自动重试。
- 管理员可中止排队、提交、运行和恢复任务；页面必须二次确认。
- 只有 `cancelled/succeeded/failed` 可以删除；删除后不再出现在列表。
- 成功任务存在公开视频 URL 时显示播放按钮并在新标签页打开。

- 对外 V2 API 新增重新执行接口。
