# 任务生命周期闭环 PRD 增量

## 1. 运维目标

管理员必须能够区分真实运行、故障恢复和本地假运行，并能在私有模型服务崩溃时使任务进入明确终态。系统应优先自动恢复，不要求管理员依赖数据库或重启前置服务清理任务。

## 2. 功能需求

### 2.1 自动恢复

- 前置服务为每次模型提交关联并持久化私有 `job_id`。
- 私有服务不可访问时显示“恢复中”，恢复后查询指定任务，而非只依据全局队列数量。
- 指定任务完成时绑定视频；失败时同步失败；不存在时先检查 Gallery，再自动重试一次。
- 自动重试次数跨前置服务重启保留，最多一次。
- 单次执行超过 10 分钟时按卡死处理；私有服务持续不可用超过该保护窗口时任务失败。

### 2.2 管理操作

- 排队、提交、运行、恢复中的任务可中止。
- 中止必须由页面二次确认；正常时精确中止私有 `job_id`，私有服务不可用时仍需完成本地终止。
- 已中止、成功和失败任务可删除；其他状态拒绝删除。
- 删除为逻辑删除，不删除上游物理视频。

### 2.3 视频访问

- 成功任务存在公开结果 URL 时显示播放按钮。
- 点击播放在新标签页打开视频地址；不得把内部私有 URL 返回浏览器。

## 3. 状态展示

监控台在现有 V2 状态之外展示管理阶段：`排队中`、`提交中`、`运行中`、`恢复中`、`重试 1/1`、`中止中`、`成功`、`失败`、`已中止`。自动刷新不得重复提交操作或关闭确认对话框。

## 4. 兼容性

- 对外 V2 状态仍只有 `queued/running/succeeded/failed/cancelled`。
- `dispatching/reconciling/cancelling` 对外映射为 `running`。
- 现有未结束任务没有 `job_id` 时使用独占实例、活动任务和 Gallery 基线进行一次兼容恢复。
