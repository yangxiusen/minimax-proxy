## 2. 变更背景

当前 Proxy 对外 API Key 以明文形式配置在 YAML，服务启动时加载到两个 HTTP Handler 的固定内存切片。新增、停用或撤销 Key 必须编辑配置并重启服务，管理后台无法查看或维护调用方凭据，实际配置和 Docker 环境中也残留无用或敏感字段。

本变更在 `/manager` 顶栏增加独立“密钥管理”入口，将外部 Key 的元数据和不可逆摘要持久化到 SQLite，并通过单进程原子内存快照完成高频鉴权。管理员只输入唯一名称，服务端生成高熵 Key，完整 Key 仅在创建成功时展示一次。

## 3. 已确认决策

- 目标版本为 `v0.0.1`，影响管理员和所有 `/v2/*` 调用方。
- 支持创建、重命名、启用、停用和删除；有任务或幂等记录引用时禁止删除，只能停用。
- 名称大小写不敏感且全局唯一，可修改；内部 ID 由服务端生成且不可修改。
- 新 Key 格式为 `mmx_` 加 64 位随机十六进制字符。
- 数据库仅保存 SHA-256 摘要、前缀和尾部指纹，不保存明文或可解密密文。
- 创建响应和一次性弹窗是完整 Key 的唯一展示位置，关闭后无法恢复。
- 鉴权使用启动时加载、管理操作后同步刷新的不可变内存快照；当前部署限定为单 Proxy 进程独占 SQLite。
- 允许没有任何启用 Key；此时管理后台可用，所有 Bearer 鉴权失败并返回 `401`。
- 旧 YAML `api_keys` 在升级后首次启动时全量、原子导入；成功后数据库成为唯一来源。
- 配置执行安全清理：移除新部署的 `api_keys` 和无引用 Docker 变量，保留 `generation_profiles` 与旧节点导入兼容。

## 6. 变更详情

### 6.1 变更前

- YAML `api_keys` 是运行时唯一来源，Key 以明文或环境变量展开值存在。
- V2 任务接口与文件下载 Handler 各自复制一份固定摘要列表。
- 任何 Key 变更都需要编辑配置并重启。
- Key 的 `id` 同时承担显示名称和历史任务归属标识。

### 6.2 变更后

- SQLite 是导入完成后的唯一 Key 真相源。
- 管理员通过后台输入名称创建 Key；完整 Key 仅展示一次。
- 名称与不可变内部 ID 分离，历史任务继续关联内部 ID。
- V2 任务接口和文件下载共用线程安全鉴权快照。
- 管理写操作使用乐观锁，正常成功响应前必须让当前进程使用新快照。
- 删除在同一数据库事务中检查任务和幂等记录引用，避免竞态。
- YAML 只在未完成首次导入时读取旧 Key；导入完成后其内容不影响鉴权。

### 6.3 不在本次范围

- Key 过期时间、调用额度、接口 scope、IP 白名单或调用统计。
- 查看、恢复或重新显示完整 Key。
- 自动轮换、双 Key 灰度窗口或主动通知调用方。
- 多管理员、RBAC、独立审计查询页。
- 多 Proxy 进程或多副本共享 SQLite 的缓存通知。
- 删除仍有历史引用的 Key 或改写历史任务归属。
- 将 `generation_profiles` 迁出 YAML。

## 7. 兼容性、风险与回滚

- 公共 `/v2/*` 路径、Bearer Header 和响应结构保持兼容。
- 旧 Key 首次启动原样导入，内部 ID 沿用旧 `id`，无需改写 `video_tasks.api_key_id`。
- 旧 ID 只做非空和长度兼容校验；新建 ID 使用服务端随机格式，不能用新格式规则拒绝既有 ID。
- 任一旧 Key 冲突或无效时整批回滚并拒绝启动，防止部分调用方丢失权限。
- DB 写入成功但缓存刷新失败时管理 API 返回 `503 cache_refresh_failed`，不宣称操作已生效；服务保留上一份只读快照并重试刷新。
- 当前只支持单进程独占数据库；绕过管理 API 修改 SQLite 后需要重启服务。
- 回滚窗口内保留旧配置备份。回滚旧二进制前恢复含 `api_keys` 的配置；新表可由旧二进制忽略。

## 8. 验收标准

- Given 旧配置含合法 Key，When 新版本首次启动，Then 所有旧 Key 可继续鉴权且导入不会重复执行。
- Given 管理员输入唯一名称，When 创建 Key，Then 返回一次完整 Key，数据库中不存在明文。
- Given 已创建 Key，When 停用并成功刷新缓存，Then 后续 V2 和 Bearer 文件下载请求立即返回 `401`。
- Given Key 被重新启用，When 使用原 Key 请求，Then 当前进程无需重启即可鉴权成功。
- Given Key 有任务或幂等引用，When 管理员删除，Then 返回 `409 key_in_use` 且数据不变。
- Given Key 无引用，When 管理员携带正确版本删除，Then记录被物理删除且快照同步更新。
- Given 没有启用 Key，When 访问管理后台和 V2，Then后台仍可创建 Key，V2 统一鉴权失败。
- Given 新部署配置，When 启动服务，Then不要求 `api_keys` 或废弃上游环境变量。
