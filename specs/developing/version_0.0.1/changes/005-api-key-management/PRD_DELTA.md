# 对外 API Key 管理 PRD 增量

## 1. 基本信息

| 项目 | 内容 |
| --- | --- |
| 目标版本 | `version_0.0.1` |
| 变更编号 | `005-api-key-management` |
| 文档类型 | `PRD_DELTA.md` |

## 2. 背景与目标

外部调用凭据目前由部署人员直接维护 YAML，管理员无法在线完成创建和撤销，也无法避免明文长期保存在配置中。本次将 Key 生命周期纳入现有管理后台，使凭据变更无需重启，并保持已有调用方和历史任务归属兼容。

## 3. 角色与场景

| 角色 | 场景 | 目标行为 |
| --- | --- | --- |
| 管理员 | 新增调用方 | 输入唯一名称，获得一次性完整 Key |
| 管理员 | 临时阻断调用 | 停用 Key，当前 Proxy 进程立即拒绝后续请求 |
| 管理员 | 恢复调用 | 重新启用原 Key，无需生成或下发新值 |
| 管理员 | 清理无用记录 | 无历史引用时删除；有引用时改为停用 |
| API 调用方 | 使用 Bearer Key | 公共 V2 调用方式保持不变 |
| 部署人员 | 版本升级 | 旧 YAML Key 自动导入且调用不中断 |

## 4. 需求增量

### 4.1 密钥列表

- 顶栏新增“密钥管理”按钮，打开独立对话框。
- 列表显示名称、掩码、状态、创建/更新时间和可用操作。
- 不显示摘要、完整 Key 或内部数据库细节。
- 没有启用 Key 时显示明确警告，但不阻止管理员操作。

### 4.2 创建

- 管理员只输入名称；名称去除首尾空格后不能为空。
- 名称大小写不敏感且全局唯一。
- 服务端生成 Key 和不可变内部 ID。
- 完整 Key 仅在创建成功响应和随后的一次性弹窗中出现。
- 关闭弹窗前要求确认已保存；关闭后不能再次查看。

### 4.3 重命名与启停

- 名称可修改，内部 ID 和历史任务归属不变。
- 启停使用记录版本做并发控制；过期页面提交返回冲突并要求刷新。
- 允许停用最后一个启用 Key；此时公共 Bearer 请求全部失败。
- 启用恢复使用同一个原始 Key，系统不会再次展示该值。

### 4.4 删除

- 删除是物理删除，仅允许无 `video_tasks` 和 `idempotency_keys` 引用的 Key。
- 有引用时返回明确冲突，不级联、不改写历史数据，页面建议停用。
- 删除前显示名称和掩码并要求确认。

### 4.5 升级与配置清理

- 旧 YAML Key 只在一次性导入未完成时使用。
- 导入全量成功后写持久化标记，后续以数据库为唯一来源。
- 新安装没有 Key 也可以启动，由管理员进入后台创建。
- 示例和新部署配置不再包含 `api_keys`；实际部署文件在人工确认导入后清理。
- 删除 Docker 中已无引用的外部 Key和旧上游 URL 环境变量。

## 5. 不在范围

- Key scope、限额、有效期、使用统计、自动轮换和批量导入。
- 将管理员密码、队列、任务参数或生成配置迁移到后台。
- 多实例缓存同步。

## 6. 验收标准

- 管理员可完成创建、复制一次性 Key、重命名、启停和受保护删除。
- 完整 Key 关闭后无法从页面或接口重新获取。
- 停用成功后，新请求即时失效；重新启用后无需重启恢复。
- 历史任务始终显示稳定的内部 Key ID，不因重命名变化。
- 零启用 Key 时页面警告清晰，管理后台仍可恢复服务。
- 旧 YAML Key 导入过程全有或全无，不发生部分迁移。
