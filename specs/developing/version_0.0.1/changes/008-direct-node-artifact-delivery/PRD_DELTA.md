# 节点直出视频产品需求增量

## 1. 基本信息

| 项目 | 内容 |
| --- | --- |
| 目标版本 | `version_0.0.1` |
| 变更编号 | `008-direct-node-artifact-delivery` |
| 文档类型 | `PRD_DELTA.md` |

## 2. 变更背景

- 当前视频经 Proxy 流式转发，持续消耗 Proxy 出口带宽。
- 节点本身保存最终视频并在 `7860` 提供文件能力，因此视频正文无需二次经过 Proxy。
- 节点内部文件接口受 Node Key 保护，不能将内部地址或 Key 直接交给客户。

## 3. 本次目标

- 将成功视频的传输出口从 Proxy 调整为产物所在节点。
- 保留临时授权、任务归属和 Range 播放能力。
- 消除 Proxy 公共根地址配置，降低生产部署配置量和视频流量成本。

## 4. 变更范围

### 4.1 本次包含

- V2 单任务查询、V2 任务列表和 Manager 任务列表中的视频 URL。
- Node `7860` 上的公开签名下载路由。
- 固定 48 小时有效期、有效期内重复访问、单 Range 播放和下载。
- Proxy Docker、本地示例配置和部署文档中的公共根地址清理。

### 4.2 本次不包含

- 页面改版、数据库迁移、CDN、对象存储或永久公开下载。
- 为内部与外部分别配置两个节点地址。
- 对外开放 Node 内部执行、健康、导入、删除或维护接口。

## 5. 需求增量说明

### 5.1 变更前

- 成功任务返回 Proxy 签名地址。
- 调用方从 Proxy 下载，Proxy 再从 Node 拉取并转发。
- Proxy 必须配置调用方可达的 `MINIMAX_PUBLIC_BASE_URL`。

### 5.2 变更后

- 成功任务返回产物所在节点的临时签名地址。
- 调用方直接从 Node 下载，Proxy 只负责 API 鉴权、任务查询和签名计算。
- 链接从签发时起 48 小时有效，可重复访问并可被转发；到期后重新查询任务获得新链接。
- 数据库中的节点 `service_url` 必须同时被 Proxy 与外部调用方访问。

### 5.3 角色与场景

| 角色 | 场景 | 目标行为 |
| --- | --- | --- |
| 外部 API 调用方 | 查询成功任务 | 获得可直接播放或下载的 Node 签名 URL |
| 外部链接持有者 | 48 小时内访问 | 无需 Node Key，可重复访问视频 |
| 管理员 | 在 Manager 播放成功视频 | 保持现有按钮和弹窗体验，视频由 Node 直出 |
| 部署人员 | 配置节点 | 保证数据库中的根 `service_url` 对外可达，无需配置 Proxy 公共根地址 |

## 6. 验收标准

- Given 用户查询成功任务，When 打开 `content.url`，Then 网络连接的文件响应来源是对应节点而非 Proxy。
- Given 用户拖动视频进度条，When 浏览器发送 Range，Then 节点返回正确的 `206` 和 `Content-Range`。
- Given 链接签发未超过 48 小时，When 多次访问或转发链接，Then 均可访问同一活动视频。
- Given 链接已过期，When 再次访问，Then 被拒绝；重新查询任务后获得可用的新链接。
