## 2. 目标与角色

运维管理员需要在不读取服务器日志的情况下确认任务积压、节点可用性和任务归属。唯一新增角色为“管理员”，权限为只读查看，不允许操作任务或私有节点。

## 3. 功能需求

### 3.1 登录

- 使用 YAML 配置的管理账号密码，默认 `admin` / `123`。
- 登录成功建立受保护会话；退出后立即失效，服务重启后会话失效。
- 生产部署应通过环境变量替换默认密码。

### 3.2 全部任务

- 显示任务 ID、客户标识 `api_key_id`、状态、实例、生成方式、规格和创建时间。
- 支持状态、实例筛选，并按任务 ID 或客户标识搜索。
- 默认每页 10 条，可切换 10/20；按创建时间倒序。

### 3.3 私有服务监控

- 私有服务区域与全部任务使用不同外层容器。
- 节点列表显示健康/异常/未知、空闲/运行中及私有队列数。
- 节点详情显示地址、最后检查时间、CPU、内存、GPU、显存、当前任务、最近错误和最近一条已结束任务。
- 字段无法获取时显示“未知”或 `--`，不把缺失数据当作 0。

### 3.4 资源不足

- 所有节点异常或尚未完成首次探测时，不接收新任务并返回 HTTP 503。
- 存在健康节点时允许任务排队，不以节点忙碌作为拒绝条件。

## 4. 非功能要求

- 页面与管理 API 由同一 Go 二进制提供，不依赖 Node.js 或 CDN。
- 监控只读，不增加数据库表；状态缓存丢失不影响任务真相源。
- 敏感信息脱敏，原始上游日志不得返回前端。

## 5. 验收标准

- 管理员可在一个页面完成全局与单节点排查。
- 节点内不出现第二套分页；完整历史通过上方实例筛选查看。
- 缓存更新时间和数据未知状态清晰可辨，异常不会导致页面空白。
