## 2. 背景与目标

当前服务仅通过日志观察节点和任务，无法集中确认私有服务连接、资源、队列及任务归属。新增 Go 内置只读监控页，以图形指标和列表呈现全局任务及单节点状态，不引入独立前端运行时。

目标是让管理员快速识别全部任务、异常节点和节点最近执行情况，并让任务创建接口在所有节点均未通过健康检查时返回明确的资源不足错误。

## 4. 变更详情

- 管理员以 YAML 中的账号密码登录，只能读取监控数据。
- 顶部“全部任务”支持状态、实例、任务 ID/客户筛选，每页仅允许 10 或 20 条。
- “私有服务监控”使用独立外层区域；左侧选择节点，右侧显示连接状态、运行状态、CPU、内存、GPU、显存、私有队列、当前任务和最近一条已结束任务。
- 后端每 5 秒更新内存状态缓存；页面每 5 秒读取一次。原始上游日志不返回浏览器。
- 节点启动后首次探测前为 `unknown`，不计入可用节点。只要存在健康节点，即使其忙碌，仍允许任务排队；全部节点异常或未知时创建接口返回 HTTP 503。

## 5. 不在范围

- 监控页写操作、节点启停、取消任务和配置编辑。
- 精确生成进度、ETA、GPU 温度、磁盘、驱动版本及历史趋势图。
- 从私有队列反查任务 ID；私有 API 目前只提供队列数量。
- 修复上游生成失败后可能长期轮询的问题，另立缺陷处理。

## 6. 兼容性与风险

- 原有四个 `/v2` 路径和成功响应保持不变；新增 503 只影响无健康节点时的创建请求。
- 节点资源字段来自私有接口，解析失败时字段显示未知，不能伪造数值。
- 管理会话仅存内存，服务重启后需重新登录。回滚时移除监控路由、采集器和创建前可用性检查即可，SQLite 无需回滚。

## 7. 验收标准

- 管理员登录后可查看全局任务和节点信息，未登录访问数据接口返回 401。
- 页面筛选、10/20 分页及 5 秒刷新正常，节点详情只展示当前任务和最近一条已结束任务。
- 多节点中任一节点健康时创建请求可入队；全部节点异常或未知时返回 503 `resource_unavailable_error`，提示“资源不足，请稍后重试”。
- 页面不暴露 API Key 明文、管理密码、上游原始日志或内部视频地址。
